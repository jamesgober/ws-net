# ws-net v0.7.0 - Hardening

**Attacked on purpose.** v0.7.0 added ten fuzz targets, one test per
threat in the threat model, a soak of 100,000 connection pairs, and a
big-endian check. Two independent reviewers then read the engine and the
handshake against the threat model. They found twelve defects. None could
crash the process or run code (the crate forbids `unsafe`), and all twelve
are fixed with a regression test each. `docs/SECURITY.md` records the
threat model, every defense with its test and cost, and the results.

## The record

- **Fuzzing.** Ten cargo-fuzz targets ran 24 hours each on the fixed code:
  the frame header; the connection in both roles under small, default, and
  lifted budgets; API call sequences; the server and client heads; extension
  parsing; the Origin policy; handshake keys; and a differential target
  against tungstenite 0.30.0. 35.32 billion inputs in all: no crash, no
  timeout, no artifact.
- **Soak.** 100,000 live connection pairs for 4 hours on the fixed code:
  8.5 billion steps, 144 million connections closed and replaced. The heap
  held at 1.86 GB throughout; its late mean is within 0.02% of its early
  mean.
- **Conformance.** The Autobahn TestSuite runs in CI in both roles, strict:
  301 cases, 0 failures.
- **Big-endian.** The frame codec, masking, SHA-1, base64, and key tests
  pass under Miri on `s390x-unknown-linux-gnu`.
- **Attacks.** `tests/attacks.rs` has one test per threat T-1 to T-29.
  T-19 to T-21 wait for permessage-deflate (1.1).

## Fixed by the review

- **A closed connection that cannot write.** A connection that failed with
  output unwritten (an idle timeout, a protocol error) had no timer left, so
  a peer that never read held the transport open. The close timeout now
  stays armed after `Closed` while output is unwritten, or while a client
  waits for the server's EOF. `next_deadline` reports it.
- **Room to close.** A client's masked Pong and Close are 131 bytes each;
  the 256-byte headroom above `max_output` fit one, not both. It is 262.
- **A keepalive Ping that does not fit** left its deadline in the past, so
  a timer loop woke on every tick. It now counts as sent.
- **Refused calls change nothing.** A send that failed part way (a
  masking-key refill error) is rolled back, and a refused Close no longer
  counts as sent. An invalid UTF-8 message is no longer left for
  `detach_message`.
- **Wiping.** `wipe` zeroes each buffer's whole allocation, the spare
  capacity included.
- **The handshake.** A server accepts origin-form request targets only:
  absolute-form, authority-form, and `*` are `MalformedHead`. An
  absolute-form target carries an authority that would override the `Host`
  the policy checked. `HeadReader` keeps its error until `reset`. Extension
  offers spread over several fields re-parse.
- **Logs.** `ServerHandshake`'s `Debug` prints the path without the query,
  and `ClientHandshake`'s prints header names only.
- **DNS rebinding.** The `accept` documentation says that the Tier 1 policy
  accepts any `Host`, and that a service on a private address needs
  `AcceptPolicy::with_hosts`.

Found by the new attack tests: `should_close_transport` stayed false after a
close timeout while the unanswered Close was still queued.

## Compatibility

Two behavior changes, both stricter. A request target that is not
origin-form is refused (no WebSocket client sends one). The output may
exceed `max_output` by 262 bytes instead of 256. `next_deadline` returns
the close deadline after `Closed` while output is unwritten, where it
returned `None`. A caller that sleeps until then and calls `on_time` sees
`should_close_transport` turn true when it passes. No API change.

## Moved to 0.8

The tls-net example (FR-46) and the end-to-end benchmark over net-io. Both
