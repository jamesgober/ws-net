# ws-net v0.9.0 - Beta

**Compression, and the API as it will freeze.** v0.9.0 adds
permessage-deflate (RFC 7692) behind the `deflate` feature, finishes the
1.0 API in `docs/API.md`, and comes with a fresh security review, a
performance pass, and long fuzz and socket runs. Changes to the API from
here need a reason recorded in `docs/STABILITY-1.0.md`. Code written for
0.8 builds unchanged, except where it keeps a temporary `Negotiated` passed
to `ServerHandshake::response_fields` (see Changed).

## permessage-deflate

- **Feature `deflate`**, on compress-lib 0.7 (first party, no dependencies,
  `no_std` + `alloc`). Without the feature nothing changes and nothing
  extra is compiled.
- **Negotiation in both roles** with all four parameters and window bits 8
  to 15: `AcceptPolicy::with_deflate`, `ClientHandshake::with_deflate`,
  `DeflateConfig`, `DeflateParams`, `Negotiated::deflate`. No context
  takeover unless configured, so an idle connection holds no window.
- **Sends** compress by `SendOptions` and a minimum size (256 bytes);
  `PreparedMessage::with_deflate` compresses a broadcast once.
- **Receives** inflate into the reassembly buffer with the output capped
  at `max_message` while it runs (1009), so a decompression bomb stops at
  the budget instead of after it. Text is validated once inflated. Data
  that is not valid DEFLATE fails with `WsError::InvalidCompressedData`
  (1007).
- **Conformance**: Autobahn sections 12 and 13 (the deflate cases) in CI,
  both roles, strict.

## Checked

- **Security review.** A fresh review read the whole crate, deflate
  included, and found eight defects. All are fixed with a test each; none
  reaches a crash (the crate forbids `unsafe`). They include a connection
  made without `with_keepalive` that never timed out its Close, an input
  buffer compacted on every feed (quadratic for a caller feeding after each
  event), and a compressed message counted before it was known valid.
  `docs/SECURITY.md` lists them all.
- **Fuzzing.** Eleven targets, the new `deflate_message` included, ran
  clean: 32 hours each (25 for `deflate_message`), 14.55 billion inputs,
  before a host restart cut the 72-hour runs short. The 72-hour runs have
  restarted and close before 1.0.
- **Sockets.** On net-io, 500 clients: the blocking pool for 24 hours on
  Linux (8.58 billion messages, heap 194 to 197 MB), and both drivers for
  4 hours on Windows with a flat heap.
- **Consumers.** serve-net's upgrade route (22 tests) and the editor tool
  build and pass on the 0.9 API without a change.

## Measured

- **Small-message receive is 14 to 24% faster than 0.8.0** on the hosted
  runners: a single-frame text message is validated once instead of twice.
- **Against tungstenite 0.30.0** in the same run: 1.75 to 2.44 times as
  fast receiving small messages, 1.61 to 4.85 times sending them, and
  level to 1.48 times on the handshake, where ws-net checks more. Every
  remaining shortfall is listed with its cause in `docs/PERFORMANCE.md`.

## Changed

- A connection's timers start with the 5 s close timeout armed, without
  `with_keepalive`.
- The input buffer is compacted only when half of it is read or when what
  is left cannot be parsed.
- A client fails a response whose `Upgrade` names anything but
  `websocket`.
- `ServerHandshake::response_fields` borrows the `Negotiated` it is given
  for as long as the fields live. A temporary `&Negotiated::none()` kept
  past its statement must be bound to a variable first.
- Every rustdoc example runs, the `blocking` examples over loopback.

## Added

- `Sender::send_text_with` and `send_binary_with`;
  `blocking::WebSocket::send_text_with`, `send_binary_with`, and
  `with_keepalive`.
- `docs/STABILITY-1.0.md`: what stands between this beta and 1.0.

## Fixed

- `blocking::connect_with` built the client connection without the
  negotiated extensions.
