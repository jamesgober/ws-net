# ws-net v0.4.0 - Extended

**Everything around the protocol that a busy server needs.** v0.4.0 added
an output budget, memory release, keepalive and timeouts on the caller's
clock, a split borrow for replying while holding a message, detaching
messages into the caller's buffers, counters and wiping, owned and prepared
messages, extension parsing, Host allowlists, a blocking adapter, and an
integration test with http-net.

## Bounded in both directions

0.2 bounded what a peer sends; 0.4 bounded what this end holds for a peer
that stops reading. A send that would take the pending output over
`Limits::max_output` (32 MiB by default) was refused with
`WsError::OutputFull` and changed nothing. Automatic Pongs and Close frames
kept a 256-byte headroom, so a flooded connection could still answer and
close. `Limits::with_input_buffer` sized the input buffer (256 B to 1 MiB),
`with_retain` set how much capacity a buffer keeps after a burst, and
`release_memory` freed every empty buffer: an idle connection then held no
heap at all. A counting-allocator test measured each case, and checked that
receiving and sending small messages allocates nothing in steady state.

## Keepalive without a clock

The engine still owns no clock. `Connection::on_time(now)` applied a
`Keepalive` (ping interval, idle, close, and message timeouts) at the
caller's monotonic milliseconds, and `next_deadline()` said when to call
again, so a driver sleeps until there is work. The message timeout ended a
slow message holding its budget (1008); the idle timeout queued 1001; the
close timeout cut off a peer that never answers a Close.
`should_close_transport()` said when to close the socket (a server first).

## For gateways and engines

- `poll_split()` returned the event and a `Sender`, so a handler could reply
  while it still borrowed the message.
- `detach_message(&mut buf)` moved a delivered message into the caller's
  buffer: a swap for reassembled messages, one copy otherwise.
- `stats()` counted bytes, frames, messages, Pings, Pongs, and Closes, for
  rate limits.
- `wipe()` zeroed every buffer and the masking seed before ejecting a
  connection.
- `PreparedMessage` encoded a broadcast once; `send_prepared` appended it
  with one copy per connection (about 60 ns per subscriber in the
  `broadcast` example on a loaded Windows machine).

## Handshake

- `AcceptPolicy::with_hosts` refused a `Host` that is not one of the
  server's names (DNS rebinding, 403); `with_secure` pinned the page's
  scheme under the same-origin rule; `with_keepalive` configured accepted
  connections.
- `Sec-WebSocket-Extensions` was parsed and validated (at most 16 offers of
  16 parameters) and exposed through `ServerHandshake::extensions` and the
  new `extension` module. No extension was negotiated yet: every offer was
  declined, as RFC 6455 allows.
- `response_fields` gave the `101`'s fields for an HTTP layer that writes
  the status line; `write_response_with` and `ClientHandshake::with_header`
  added extra headers, refusing the names the handshake writes itself.
- `write_refusal` wrote 403, 429, or 503 with `retry-after`.

## Blocking adapter and http-net

The `blocking` module drove a connection over any `Read + Write` stream:
`accept` (same-origin policy, linear head scanning), `connect`, `read`
returning owned `Message`s, and the sends. `WebSocket::from_upgraded`
continued after http-net's `on_upgrade` hand-off. `tests/http_net.rs`
exercised both the sans-IO `ServerConn` upgrade and the blocking server
against http-net 0.9, a dev-dependency only; `docs/INTEGRATION.md`
described each composition.

## Compatibility

| Change | Before | Now |
|---|---|---|
| Sending past 32 MiB of unwritten output | queued | `OutputFull` (raise it with `with_max_output(u64::MAX)`) |
| A reassembly buffer after delivery | kept up to 1 MiB | kept up to `retain` (64 KiB) |
| The automatic Pong | encoded at the next `output()` | encoded when the Ping is read; same bytes on the wire |
| `Verified`, `Decision` | `protocol` only | also `extensions` (both `#[non_exhaustive]`) |

## Measurements

The benchmark comparison with 0.2.0 was not conclusive: the runs shared a
machine at a load average near 40 on 32 cores, where an unchanged 0.2.0
benchmark moved by up to 350% between back-to-back runs. The per-message
additions of this release (an output-budget check per send, counters) are
re-measured on a quiet machine in 0.6, which fixes any row more than 5%
behind 0.2.0. The new benchmarks (`broadcast/prepared_10k`,
`keepalive/on_time_idle`, `flood/empty_continuations`,
`handshake/head_reader_bytewise`) were added for that run.

## Dependencies

Unchanged: `parse-net` 0.9 and, with `std`, `mod-rand` 1.0. http-net 0.9 is
a dev-dependency for the integration test and one example.
