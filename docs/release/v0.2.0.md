# ws-net v0.2.0 — A Sans-IO WebSocket Engine

**The foundation.** v0.2.0 turns the scaffold into a complete WebSocket
(RFC 6455) protocol engine that does no I/O: the opening handshake,
standalone over raw bytes or behind an HTTP layer; frame parsing and
serialization; masking; fragmentation with incremental UTF-8 validation;
ping/pong; and the closing handshake. Every protocol rule is enforced with
the right close code, every size is bounded from frame headers, and the
crate has no dependencies.

## What is ws-net?

The WebSocket layer of the owner's `-net` network family, and the transport
of LexerSketch Studio, which runs one WebSocket per window carrying
JSON-RPC text frames and binary stream frames (decisions D23/D24). It is
sans-IO: the caller owns the socket, so the same engine serves a blocking
`std::net` server, an async runtime, or a test that feeds it one byte at a
time. HTTP is `http-net`'s job; the handshake composes with it through
plain `(name, value)` fields, and works without it over raw head bytes.

## What's new in 0.2.0

### `Connection` — one WebSocket, both roles

Bytes go in through `feed` (or `read_buf` + `commit`, to read a socket with
no copy) and `feed_eof`; `poll` returns `Event::Text`, `Binary`, `Ping`,
`Pong`, `Close`, `NeedInput`, or `Closed`; `send_text`, `send_binary`, the
fragment variants, `send_ping`, `send_pong`, and `close` queue frames; and
`output` + `advance_output` drain them to the socket. A single-frame message
already in the buffer is unmasked in place and lent out with no copy.

```rust
use ws_net::{Connection, Event};

let mut server = Connection::server();
let mut client = Connection::client_with_seed([42; 32]);
client.send_text("hello")?;
let wire = client.output().to_vec();
client.advance_output(wire.len());
let _ = server.feed(&wire);
assert!(matches!(server.poll()?, Event::Text("hello")));
# Ok::<(), ws_net::WsError>(())
```

### Every rule, with its close code

Masking direction per role, RSV bits, reserved opcodes, control frames
fragmented or over 125 bytes (or using an extended length field at all),
payload lengths not minimally encoded or with the 64-bit high bit set,
fragment order with control frames interleaved, UTF-8 validated
incrementally across fragment boundaries (an invalid byte fails at once,
1007), and the Close payload, code, and reason. A violation queues the Close
frame with its code (1002, 1007, 1009), the error is reported once, and the
connection is finished. Non-minimal length encodings are refused by policy:
RFC 6455 says the minimal encoding MUST be used.

### Budgets from headers

`Limits` sets the frame budget (1 MiB by default) and the message budget
(16 MiB), Studio's numbers. Both are checked from frame headers before any
payload is read, so a fragmented message cannot be used to exhaust memory.
Reassembly reserves at most 1 MiB ahead of the bytes that have arrived,
even with the budgets lifted; the input buffer is capped at 64 KiB; and an
automatic Pong still waiting at the end of the output is replaced by the
next one, so a peer that pings without reading cannot grow the queue.

### Failures versus refused calls

A `WsError` is either a connection failure, with `close_code()` naming the
code that was sent (or 1006, never sent, for a transport that ended early),
or a refused call (`InvalidArgument`, `InvalidState`) that sent nothing and
changed nothing: an oversized Ping, a reserved close code, a send after
Close.

### The opening handshake, with the server's policy inputs

`ServerHandshake::from_head` validates an upgrade request from the raw bytes
off the socket, through a strict, bounded HTTP/1.1 head reader (16 KiB, CRLF
only, no folding, no whitespace before a colon); `from_request` takes the
method, target, and fields from an HTTP layer, in the exact shape `http-net`
yields. Both check `GET`, one `Host`, `Upgrade` and `Connection` tokens
(case-insensitive, lists), version 13, one key that is the canonical base64
of 16 bytes, at most one `Origin`, and token subprotocols. The result
exposes `target`, `host`, `origin`, and the offered `protocols` for the
server's policy (Studio checks `Host` against DNS rebinding and `Origin`
against cross-site hijacking), and `write_response` writes the `101` with an
offered subprotocol or none. `HandshakeError::write_response` writes the
refusal (400, 426 with `sec-websocket-version: 13`, or 431).

`ClientHandshake` writes the request (`with_protocols`, `with_origin`) and
checks the response with `verify` or `verify_head`: status 101, the
`Sec-WebSocket-Accept` value, no extension, at most one offered subprotocol.

```rust
use ws_net::{ClientHandshake, ServerHandshake};

let client = ClientHandshake::with_nonce(*b"the sample nonce").with_origin("http://127.0.0.1:8080");
let mut request = Vec::new();
client.write_request("127.0.0.1:8080", "/rpc", &mut request)?;
let (server, _) = ServerHandshake::from_head(&request)?.expect("complete");
assert_eq!(server.origin(), Some("http://127.0.0.1:8080"));
assert_eq!(server.accept_key().as_str(), "s3pPLMBiTxaQ9kYGzzhZRbK+xOo=");
let mut response = Vec::new();
server.write_response(None, &mut response)?;
assert_eq!(client.verify_head(&response)?, Some((None, response.len())));
# Ok::<(), ws_net::HandshakeError>(())
```

### The frame codec

The `frame` module exposes `Opcode`, `FrameHeader` (`decode`, `encode`,
`encoded_len`; every encoded header decodes), and `apply_mask`, which masks
eight bytes at a time and accepts any offset, so a payload can be unmasked
in pieces.

### SHA-1 and base64, in the crate

The handshake needs SHA-1 and base64. Both are small private modules —
SHA-1 checked against RFC 3174's vectors, base64 strict and canonical
against RFC 4648's — until the owner's crypto and codec libraries provide
them. A client's masking keys come from SHA-1 in counter mode over a secret
seed drawn from the OS (feature `std`) or supplied by the caller.

### Examples

`sans_io` runs a client and a server through memory: the handshake as raw
bytes, messages, a ping, a refused call, and the closing handshake.
`echo_server` is a localhost echo server over `std::net` with no HTTP
library, answering refusals and closing protocol failures with their code.

### Tests and verification

- **Autobahn-style cases as data.** 111 cases covering framing, ping/pong,
  reserved bits and opcodes, fragmentation, UTF-8 (including fail-fast
  inside and across fragments), close codes, limits, masking direction, and
  length encoding. Each runs whole, one byte at a time, and in 7-byte
  pieces, and the three runs must agree exactly.
- **Properties for every invariant** in `dev/DIRECTIVES.md` section 4:
  messages survive any fragmentation and split in both directions; text is
  accepted exactly when `std::str::from_utf8` accepts it; budgets match a
  direct computation; arbitrary bytes and frame-shaped noise never panic,
  with budgets small, default, and lifted; every frame shape round-trips;
  masking is an involution at any offset; the parse does not depend on how
  input is split.
- **Both handshakes.** RFC 6455's own example request and accept key,
  strict-head refusals, `Host`/`Origin` rules, a client-server round trip for
  arbitrary nonces, and the closing handshake from both ends in both orders.
- **Over a real socket.** A localhost echo of text, a 3 MB binary message,
  fragments with an interleaved ping, and the closing handshake; a protocol
  failure whose 1007 Close reaches the peer; a version refusal; an `Origin`
  refusal.

### Found and fixed by the pre-release adversarial review

Each fix was preceded by a failing test, kept in `tests/regressions.rs` or
the socket tests:

- With the budgets lifted, a 14-byte header announcing a terabyte made the
  connection reserve that much up front and abort the process.
- A peer that pinged without reading grew the output by one Pong per Ping,
  without bound.
- Refused calls (an oversized Ping, an unsendable close code, an oversized
  reason) reported a close code as though the connection had failed.
- `apply_mask`, `commit`, and `advance_output` could overflow on extreme
  arguments.
- The echo server example dropped the Close frame of a protocol failure.
- The handshake did not expose `Origin` or `Host`, and had no standalone
  path over raw bytes.

## Breaking changes

**None.** v0.1.0 had no public API.

## Dependency wiring

No runtime dependencies. `http-net` is composed with, not depended on: the
handshake takes its `(method, target, fields)` shape directly. An example
and an integration test over `http-net`'s upgrade hand-off move to v0.5.0,
because `http-net` 0.2 is not yet on crates.io. The decisions are recorded
in `dev/ROADMAP.md`.
