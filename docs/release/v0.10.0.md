# ws-net v0.10.0 - Pre-1.0 polish

**The last polish before release candidates.** v0.10.0 fixes how the
client's response check reports what was negotiated, tightens memory
under a slow or hostile peer, and gives a stalled message a default
timeout. There is one breaking change, in `ClientHandshake`; most code
builds unchanged.

## Breaking

- **`ClientHandshake::verify` returns `Verified`**, the selected
  subprotocol and the negotiated extensions, instead of the subprotocol
  alone. `verify_head` returns `(Verified, usize)`. `verify_full` is gone:
  `verify` is what it was. The old forms dropped the negotiated
  extensions, so a client that offered permessage-deflate could not build
  its connection from them.

  ```rust,ignore
  // 0.9
  let protocol = client.verify(status, headers)?;
  // 0.10
  let protocol = client.verify(status, headers)?.protocol;
  ```

## Fixed

- **A frame header no longer reserves memory for the length it claims.**
  A header announcing a large payload used to reserve up to 1 MiB before
  any payload arrived, so 14 bytes per connection held 1 MiB that
  `release_memory` could not free. Reassembly now grows only as payload
  arrives, to at most eight times what arrived or the input buffer.
- **Freed buffers are zeroed.** A buffer that held message bytes went back
  to the allocator unzeroed when it was freed or regrown, so `wipe` could
  not reach those copies. Every such buffer is now zeroed first. The one
  exception is compress-lib growing its output itself when a piece
  inflates to more than four times its size.
- **Compressed text fails early.** It was checked as UTF-8 only once the
  whole message was inflated. It is now checked as it inflates, every KiB
  of compressed input and at each frame's end.
- **Docs.** The examples check the count `feed` returns instead of
  dropping it, and `feed`'s docs show the loop for a read larger than the
  input buffer. The README now says where client masking keys come from
  (the OS cryptographic source) and that the crate has no third-party
  dependencies.

## Changed

- **A stalled message times out after 60 s.** `Keepalive::new`, and so
  every connection, ends a data message that stops arriving with
  `MessageTimeout` (Close 1008). It was off. Raise it with
  `with_message_timeout`, or pass `Duration::MAX` to turn it off.
- **compress-lib 1.1.0** for feature `deflate`, which `compress-lib = "1"`
  resolves to. No source change.
- `docs/API.md` gains a "Tier 1 at a glance" table, and the README's quick
  start adds the blocking client and server.

## Checked

- **Fuzzing.** All eleven targets ran their full 72 hours on this code,
  `deflate_message` on compress-lib 1.1.0: 170.70 billion inputs, no
  crash, no timeout, no out-of-memory, no leak.
- **Sockets.** The 24-hour soak on net-io 0.7.0's reactor (Linux, 500
  clients) passed: 3.70 billion messages, heap flat.
- **Conformance.** Autobahn TestSuite, both roles, strict, in CI.

## Cost

A message larger than `retain` (64 KiB) now pays for zeroing its buffer
when it is freed, and one regrow: about 26 µs per MiB on Linux and 40 µs
on Windows and macOS. Small messages and sends are unchanged. A service
of large messages can set `Limits::with_retain` to its message size to
keep and reuse the buffer instead. The numbers are in
`docs/PERFORMANCE.md`.

## Migrating from 0.9

`docs/API.md`, "Migrating from 0.9", covers both changes: the `verify`
forms, and the 60 s default message timeout, with an example of raising
it.
