# ws-net v0.8.0 - Alpha

**On real transports.** v0.8.0 runs ws-net end to end over sockets: as a
net-io `Session` on both of net-io's drivers, over tls-net, and against
tungstenite on three platforms. Consumers can now adopt the engine as it
will ship. The changes to the engine are small: a counter fix, one
accessor, a faster send path, and parse-net 0.9.1 for extension
parameters. There is no breaking API change.

## On net-io and tls-net

- **`interop/net-io/`**: ws-net as a net-io 0.6 `Session`, short enough to
  copy. CI runs it on three platforms: every length class, 48 clients at
  once, Pings, the close order, a 403 refusal, a vanished peer, and net-io's
  idle timeout as Close 1001. `docs/INTEGRATION.md` has the mapping and the
  sizing.
- **Socket soak** (`interop/net-io/tests/soak.rs`). Four hours per driver
  on Linux, 500 clients with heavy-tailed message sizes and reconnects: 200
  million messages and 206,000 accepted connections on the reactor, 1.25
  billion messages and 1.28 million accepted connections on the blocking
  pool. The heap stayed flat: 121 MB early and 121 MB late on the reactor,
  195 MB and 188 MB on the pool. The Windows run waits for net-io 0.6.2.
- **`interop/tls/`**: a ws-net client and server through two tls-net 0.5
  sessions in memory, with the close order (Close, TLS `close_notify`,
  TCP) checked step by step.

## Measured

- **End to end** (`docs/PERFORMANCE.md`): echo round trips over loopback.
  On Linux, for messages up to 1 KiB and 16 or more connections, ws-net
  on net-io's reactor runs at 0.94 to 1.31 times thread-per-connection
  tungstenite across two hosted runs.
  At 64 KiB, net-io's output budget decides: raised above the message
  size, it is worth 19 to 27%.
- **Small sends**: the exact frame size is worked out only near the
  output budget, and each frame makes one capacity check. Client sends on
  Linux went from 14% behind 0.2.0 to 4 to 8%. The rest is the output
  budget, the slow-consumer defense, and stays.
- **The Linux 1 MiB rows** of the comparison harness are buffer placement
  on the hosted runner, not ws-net. With only the heap layout changed, the
  same code path took 753 µs in one case and 78 µs in another, with no page
  faults. `bench-compare/examples/faults.rs` measures it.

## Fixed

- A Ping, Pong, or Close whose payload arrived in pieces was counted in
  `frames_in` once per `poll` until it was whole. A Ping fed one byte at a
  time counted about 130 times, enough to trip a frame-flood limit. It now
  counts once, and the split property test compares every counter.

## Added

- `Stats::data_frames_in`. With `messages_in` and `pings_in` it gives
  fragments per message and Pings per message, which flag an abusive peer
  sooner than byte rates do.
- `tests/budget_audit.rs`: every heap growth site in `src/` names the
  budget that bounds it (78 sites), and a new one without a note fails CI.
- `docs/PLATFORM-NOTES.md`, and a net-io section in `docs/INTEGRATION.md`.

## Changed

- parse-net 0.9.1. Extension parameters are read with its optional-value
  parameter parser instead of ws-net's own loop. Everything accepted before
  is accepted with the same parameters; checked against the 0.7 fuzz corpus
  and 20 million random inputs. The one difference: empty parameters
  (`permessage-deflate;`) are now skipped instead of refused.
