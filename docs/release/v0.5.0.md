# ws-net v0.5.0 - Feature Complete

**Feature complete, and conformance checked by the Autobahn TestSuite.**
v0.5.0 added the last API items that do not depend on compression and ran
the Autobahn TestSuite in CI for both roles. Every case of sections 1 to 10
passed strictly. permessage-deflate moved to 0.6, because the first-party
DEFLATE crate it builds on did not exist yet.

## Autobahn TestSuite

The suite (`crossbario/autobahn-testsuite:25.10.1`) ran on every change in
CI:

- **Server role:** its `fuzzingclient` mode against
  `examples/autobahn_server`, an echo server on the blocking adapter with
  64 MiB budgets so the 9.x cases measure speed, not limits.
- **Client role:** its `fuzzingserver` mode with `examples/autobahn_client`,
  which runs every case as an echo client and asks the suite for its
  report.

`autobahn/check.py` failed the job on any result but OK, in both the case
behavior and the close behavior, so NON-STRICT counted as a failure. The
result was 301 cases and 0 failures in each role. Cases 7.1.6, 7.13.1, and
7.13.2 are informational by the suite's own design. Sections 12 and 13
(permessage-deflate) were excluded until the `deflate` feature exists.

## API

- `Connection::with_extensions` and `negotiated` carried what the handshake
  negotiated; connections built by `accept`, `ServerHandshake::accept`, and
  the new `ClientHandshake::connection` (and `connection_with_seed`) had it
  already. `Verified::none` built a verification by hand.
- `SendOptions` and `send_text_with` / `send_binary_with` chose compression
  per message. With no compression available yet every message went
  uncompressed, and code that asks for `SendOptions::uncompressed()` (a
  message carrying a secret, against CRIME and BREACH style attacks) keeps
  that guarantee once compression exists.
- `FrameHeader::with_rsv` set the reserved bits for an extension that
  defines them.

## Moved: permessage-deflate

RFC 7692 compression needs a raw DEFLATE implementation. The crate allows no
third-party runtime dependency, and no first-party DEFLATE crate existed on
2026-11-04, so the `deflate` feature moved to 0.6, as the roadmap's move
rule says. If one is not published by then, it moves out of 1.0 to 1.1.

## Compatibility

Additive. No behaviour changed.
