# ws-net v0.3.0 - Design Lock

**The design lock.** v0.3.0 added the one-call server accept with the
same-origin policy, a head reader whose work stays linear however slowly a
peer sends, masking seeds from the operating system's cryptographic random
source, and the shared HTTP grammar from `parse-net`. The whole 1.0 API is
now written down in `docs/API.md`, each item with the version it lands in.

## Accepting a connection in one call

`ws_net::accept(bytes)` took a socket's first bytes and returned an
`Accepted`: the `101` response to write, a server `Connection` already fed
the frames that followed the head, the number of input bytes used, and the
request for routing. `Ok(None)` meant the head was not complete yet. An
`Acceptor` did the same over a buffer that grows with each read and scanned
each byte of the head once.

## Who may connect

A browser attaches the user's cookies to a WebSocket request from any page
on any site. Without an Origin check another site's page could talk to the
server as the user (cross-site WebSocket hijacking). The Tier 1 path now
applied the same-origin rule: the page's host and port had to be the
request's `Host`. `OriginPolicy::allow` pinned exact origins, compared as
parsed RFC 6454 origins and never by substring, so lookalikes such as
`https://example.com.evil.net`, `https://example.com@evil.net`, and `null`
were refused with 403. `AcceptPolicy` also chose the subprotocol by the
server's preference and set the connection's limits; `check` gave the
decision without writing, for an HTTP layer that writes its own `101`.

## Linear work for slow heads

`from_head` scanned the whole buffer on each call, so a client sending its
head one byte per read made a server do about 134 million byte visits for a
16 KiB head (the class of CVE-2023-43669). `HeadReader` and `Acceptor` kept
their scan position; a unit test counted each byte examined exactly once.

## Other changes

- An upgrade request that declared a body (`Transfer-Encoding`, or any
  `Content-Length` but a lone `0`) was refused with 400, so a front proxy
  could never disagree with ws-net about where the frames start.
- Seeds and nonces came from `mod-rand`'s OS tier (`getrandom`,
  `getentropy`, `BCryptGenRandom`). The 0.2 seed had come from
  `RandomState`, which was documented as OS-random but is one OS draw per
  thread plus a counter and the clock. If the OS source fails, `client()`
  and `ClientHandshake::new()` now fail closed; `try_client` and `try_new`
  report it.
- Lists, tokens, and field values were read with `parse-net` 0.9: commas
  inside quoted strings no longer split, and a value that does not parse
  holds nothing. The browser handshake benchmark got 12.7% faster.
- `Limits::with_send_frame` separated the outgoing frame size from the
  incoming frame budget.
- New small items: `Connection::is_open`, `can_send`,
  `ServerHandshake::select_protocol`, `MAX_PROTOCOLS`, `Opcode::is_data`,
  frame constants, `VERSION`.

## Testing

`tests/attacks.rs` started with one test per threat this release touched.
Every protocol case now ran in pieces of every size from 1 to 15 bytes and
split in two at every point. New properties compared `HeadReader` with
`from_head` for every cut and `OriginPolicy` with a reference comparison.
CI built the docs with default features as well as all, and checked a
32-bit target.

## Compatibility

Additive except for three behaviour changes a caller may notice:

| Change | Before | Now |
|---|---|---|
| A quoted string in `Sec-WebSocket-Protocol`, `Upgrade`, or `Connection` | split at its commas | one element; a quoted protocol is not a token, so it is refused |
| A request with `Content-Length: 5` or `Transfer-Encoding` | accepted | `UnexpectedBody` (400) |
| `Connection::client()` when the OS random source fails | seeded from `RandomState` | a connection that refuses every send |

`from_head`, `from_request`, and `write_response` still applied no Origin
policy; only `accept`, `Acceptor`, and `ServerHandshake::accept` did.

## Dependencies

`parse-net` 0.9 and, with `std`, `mod-rand` 1.0: both first party, neither
with dependencies of its own. No third-party runtime dependency.
